# ClozDesign 产品方向与增长规划

日期：2026-09-19。范围：产品规划，不涉及上线或修改套餐。

## 结论与假设

建议定位：面向独立服装品牌与小型电商卖家的服装商品图工作台。近期以 T-shirt、Oversized T-shirt、Hoodie 为主，让用户从一张印花开始，制作可重复编辑的服装展示图；中期把同一设计连接到 3D、真人 Mockup、多颜色和商品图导出。

这是基于现有能力与竞品供给提出的待验证方向，不是已经由客户数据证明的市场结论。暂未获取生产 GA4、Search Console、订单、续费或用户访谈数据。访问量、流失点、付费意愿和增长幅度均不能据此确定。网页抓取版本仍显示旧导航，可能与本地及实时线上版本存在差异；具体功能观察以本地代码为准。

## 用户与竞争选择

首要用户：持续上新、需要保持同款商品颜色和印花一致的小型服装品牌。首个任务：给一个新款制作正背面、颜色变体与真人展示图。POD 卖家是相邻用户，只有匹配真实 blank 型号、版型及颜色的资产才能进一步承诺商品还原准确性；目前不要把通用模型描述为指定品牌 blank 的精确替代。

次要用户：为客户交付视觉方案的自由设计师。学生、一次性下载素材者作为自然流量，不作为付费路线主要依据。复杂制版、物理试衣、供应链协同、企业团队系统暂缓。

Pacdora 已提供服装 3D 定制与多格式展示导出；Placeit 提供广泛的 Mockup、设计、视频与 Logo 资源；Recraft 提供 AI Mockup 生成。因此，“有 3D”“模板多”“能用 AI”本身不足以构成独特优势。建议验证的差异是：服装专属工作流、设计保持一致、跨场景复用、反复上新更快。跨编辑器同步是规划能力，不能描述成现有能力。

## 产品与信息架构

导航延续 3D Models、Fashion Mockups、Tools、Pricing，突出 Start creating。Guides 不恢复到主导航，保留博客 URL、页脚、相关教程和内容内链。先不批量改 URL。

首页从任务开始：主标题建议“Create product-ready clothing mockups.”；副标题说明上传印花、调整服装、生成展示图片。主按钮直接打开默认 T 恤编辑器并允许上传；次按钮查看实际样例。避免在流程验证前使用“几秒完成”“一键全套”等时间或自动化承诺。

首页内容次序：可操作的首屏或真实演示 → 同一设计的实际输出 → 三步流程 → 三个主品类 → 免费与付费区别 → 使用案例与真实常见问题。生产交付模块改为现有能力可支持的设计沟通；有真实用户后再展示评价。

核心流程：搜索/示例 → 选择默认服装 → 上传或使用示例印花 → 首次有效预览 → 保存项目/复用设计 → 导出 → 下次上新继续使用。

近期先做好一个编辑器内的任务完成率。中期建立共同设计数据：印花文件、位置、尺寸、颜色和版本；为不同模型维护适配映射。不能假定一个坐标直接适用于所有 3D 与真人模板。先为少量成套资产验证同步质量。

## 访问增长

第一批优化 6 个已有或可承接的意图：T-shirt、Oversized T-shirt、Hoodie、Front and Back、On-model、Bulk Colorways。选择依据是与现有能力匹配，尚未以搜索量验证排序；拿到 Search Console 后按曝光、点击、进入编辑器和付费贡献调整。

每页至少提供独特真实样例、可直接启动的对应模板、支持范围、导出说明、问题解答和相邻任务入口。相同工具的不同关键词不要大量复制页面。先核查现有 URL、索引及搜索意图，重复页再决定合并与重定向。

博客集中解决具体操作问题：正背面印花、深浅色配色、同设计多色、透明背景与商品展示角度。文章入口预选相关模板，减少读完再搜索工具的步骤。

渠道先集中在 Google 搜索和一个视觉渠道，建议测试 Pinterest。每周制作一段真实操作演示与三个静态衍生图，带 UTM 指向对应工具页。用编辑成功、注册后激活和付费衡量渠道，不只看曝光。暂不同时重投入多个社交平台；广告等流程与归因验证后做小预算测试。

## 注册转化

匿名用户先选模型、上传并看到结果；免费保存、跨设备继续、复用设计时解释注册价值。注册后返回原模型和完整草稿，不进入无关工作台空白页。检查 Google 登录的生产可用性、移动端体验和失败恢复。

第一版保留现有免费带水印下载作为对照，优先测试结果出现后的保存引导。后续再单独实验是否在首次下载前注册。把所有下载立即加登录门槛，可能增加注册数却减少激活与付费，不能默认有益。

注册后的首次引导只围绕完成一个作品：继续编辑 → 保存 → 导出 → 复用。对许可接收邮件的用户，可规划草稿继续和相关新模板提醒；本规划不执行发送。

## 付费与复购

先保留 $9.90/月和 $29/月价格作为测试基线，优先解释权益、展示实际导出价值；不同时调整价格、首页和注册门槛，以免无法归因。不要把提高存储空间当作主要购买理由。

| 层级 | 用户目标 | 当前可强调的价值 | 规划中的新增价值 |
| --- | --- | --- | --- |
| Free | 验证工具能否做出想要的图 | 有限项目、带水印导出 | 更清楚的首次成功流程 |
| Pro | 为单款商品制作展示图 | 去水印、更多可保存项目 | 固定多角度导出、复用配色与品牌设置 |
| Max | 持续处理多款上新 | 更高项目和存储额度 | 批量颜色、批量导出、成套资产复用 |
| Business | 特殊资产和更大用量 | 询价 | 有真实需求后再决定团队能力 |

尚未实现的批量、跨模板同步和导出能力不得先放入已售套餐。优先推荐 Pro；若没有销售数据支持，Max 的“Most popular”应换成客观用途描述。明确 Free 总额度与付费月度额度的区别，修正“Projects refresh monthly”可能产生的范围歧义。

升级触发点：预览成功后需要无水印成品、保存额度达到限制、确实使用到已上线的批量能力。升级提示展示用户自己的作品和差异，支付完成后回到原任务继续。清楚说明续费、取消与现有项目访问规则。

是否增加一次性导出包，要先通过访谈和流失原因验证：用户如果只是偶尔做一张图，订阅不匹配；若确有该群体，再设计小额包并核算成本，不与首轮主线一起上线。高档和 AI 定价需核算存储、渲染、生成、支付费用与支持成本。

## 指标与实验

建议北极星指标：每周完成自定义作品有效导出的用户数，排除示例图、内部测试及重复事件。浏览器下载事件只能说明生成并触发下载，不能证明本地文件已保存或商品已上架。另看付费用户有效导出数和复用项目数，避免免费使用量掩盖收入问题。

| 指标 | 口径 |
| --- | --- |
| 合格流量 | 去除机器人和内部访问后，来自目标意图页面/渠道的会话；与全部会话同时报告 |
| 预览成功率 | 首次有效自定义预览用户 / 编辑开始用户 |
| 注册率 | 成功新注册用户 / 符合条件的未登录独立访客；固定统计窗口 |
| 注册后激活率 | 新注册后 7 天内完成自定义导出的用户 / 同批新注册用户 |
| 新客付费率 | 新注册后 30 天内首次支付成功用户 / 已观察完整 30 天的注册 cohort |
| 结账成功率 | 支付成功 checkout / 已创建 checkout；按唯一标识去重 |
| 留存与收入 | D7/W4 复用、续费、退款、付费取消、每访客收入、月经常性收入与贡献毛利 |

先收集 14 天基线。以用户级随机实验比较主入口、结果后保存提示、升级价值展示；每次只改变一个主要变量。目标可暂定首次有效预览率相对提升 20%，属于内部实验目标，不是行业标准或预测。预先按基线和最小可检测提升估算样本量；流量不足时采用可用性访谈和顺序迭代，不根据几单付费宣布胜出。

技术上保留现有按功能命名事件，同时在报表层映射统一漏斗阶段。新注册由后端成功创建账号确认，并区分登录；支付由验签后的真实支付事实及交易 ID 确认，区分首次购买与续费，不能用回到 success URL 或所有订阅更新事件替代收入。退款与取消单独记录。按来源、落地页、设备、用户新旧分组，不把作品内容或邮件等个人信息直接发给分析系统。

## 90 天安排与验收

| 时间 | 工作 | 验收与下一步依据 |
| --- | --- | --- |
| 第 1–2 周 | 漏斗与支付口径校准；处理批量示例误导；核验登录与草稿恢复；检查前三类核心模型 | 每个测试用户可完成上传、预览、保存、支付后继续；数据不重复且可与后台对账 |
| 第 3–4 周 | 首页任务入口、Free/Pro 价值文案、结果后保存提示；优化前三个意图页 | 首次有效预览与激活改善，错误率和每访客收入不恶化 |
| 第 5–8 周 | 小范围实现同设计多色和多角度导出；维护适配资产；推广真实演示 | 用户可导出自己设计的完整图组；记录批量使用、耗时和升级贡献 |
| 第 9–12 周 | 扩大已验证资产、意图页和渠道；验证跨场景复用与 Max 差异 | 以 cohort 付费、续费/复用、毛利判断是否继续投入 |

这是一种顺序安排，不是固定交付保证。若预览失败率高，先处理资产和性能；若激活改善而付费未改善，优先访谈价格和结果价值；若目标访客几乎不复用，重新评估订阅而不是继续堆套餐功能。

立即优先：1）结果与承诺一致；2）直接进入创作的首页；3）注册保存与返回；4）付费结果展示；5）真实批量图组。暂缓泛 AI 扩张、过多新品类、供应链平台、大规模低差异 SEO 页面。
